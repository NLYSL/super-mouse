# 01 · 产品需求文档（PRD）

> 版本 v0.1 · 2026-09-11 · 状态：草稿，待团队评审
> 本文回答"我们要做什么、做成什么样、怎么算做完"。技术实现见文档 02–04。

---

## 1. 产品定位

**SUPER MOUSE** 是一个运行在桌面上的"光标伙伴"：它把系统鼠标光标替换成一只有表情、有动作的卡通老鼠，并通过外接的脑机与毫米波雷达、以及 Claude 大模型，赋予这只老鼠四种超能力。

一句话：**"你的光标活了——它看得见你的眼睛，懂你的工作，还替你盯着身后。"**

黑客松评审角度的三个卖点：

1. **新交互**：眨眼即快捷键（"眼势"），解放双手；
2. **新智能**：光标悬停即触发懂你工作的 AI 助手；
3. **新感知**：硬件雷达 + 毫秒级"老板键"，笑点与实用性兼具，Demo 效果极强。

## 2. 目标用户与场景

| 用户 | 场景 | 痛点 | Super Mouse 怎么解 |
|---|---|---|---|
| 程序员 / 设计师 | 双手在键盘、手写板上，切换窗口/确认对话框要挪手 | 打断心流 | 眼势：双眨=点击，三眨=切窗口 |
| 打工人 | 每天固定的重复性工作（回邮件、整理日报、开项目） | 琐碎、重复 | Smart Brain：悬停应用图标，老鼠替你开工 |
| 所有开放办公区的人 | 摸鱼时老板/同事突然出现在身后 | 尴尬 | Strong Sense：0.5 秒内切回工作页面 |
| 长时间用眼者 | 盯屏幕忘记眨眼、久坐 | 眼疲劳 | （拟）Soft Heart：眨眼频率过低提醒 |

## 3. 核心概念：老鼠角色（Mouse Companion）

老鼠既是**光标本体**，也是所有模式的**反馈出口**。所有硬件事件、AI 状态都通过老鼠的表情和动作表现出来，评委一眼就能看懂系统在"想什么"。

### 3.1 角色状态机（动画状态）

| 状态 | 触发 | 表现 |
|---|---|---|
| `idle` | 光标静止 | 呼吸、甩尾巴、偶尔转头 |
| `walk` | 光标移动 | 朝移动方向奔跑，速度随光标速度变化 |
| `click` | 鼠标点击 / 眼势点击 | 爪子按一下 |
| `blink_mirror` | 检测到用户眨眼 | **老鼠跟你一起眨眼**（Sharp Eyes 的即时反馈，也是校准可视化） |
| `gesture` | 识别出眼势 | 眼睛冒星星 + 头顶浮出图标（如"🖱"、"⌘⇥"） |
| `thinking` | Smart Brain 在推理 | 头顶思考气泡"…" |
| `suggest` | Smart Brain 有建议 | 举起小牌子，牌子上是建议文字 |
| `working` | AI 任务执行中 | 戴安全帽、敲键盘 |
| `happy` | 任务完成 | 转圈、比心 |
| `alert` | 雷达发现身后有人 | 耳朵竖起 → **钻进洞里**（同时屏幕切换） |
| `peek` | 身后清空 | 从洞里探头 |
| `sleepy` | （拟）疲劳 / 久坐 | 打哈欠 |

### 3.2 光标热点（Hotspot）

老鼠的**鼻尖**是光标热点。系统光标通过 Mousecape 隐藏；如隐藏失败，退化为"伴随模式"：系统箭头保留，老鼠贴着箭头尖端跑（见文档 02 §8.2）。

## 4. 四大模式

### 4.1 👀 SHARP EYES —— 眼势（Eye Gestures）

**输入**：前额叶三电极脑机（蓝牙），获取眨眼事件（力度、时长）与信号质量；如设备提供专注度（Attention）等指标一并接入。

#### 4.1.1 眼势词表（Gesture Vocabulary）

自然眨眼每分钟 15–20 次，**单次普通眨眼永远不触发任何动作**。所有眼势都必须是自然状态下极少出现的模式：

| 眼势 | 定义 | 默认映射 | 可靠性 |
|---|---|---|---|
| `double_blink` 双眨 | 两次眨眼间隔 120–450 ms | 左键点击 | ★★★★ |
| `triple_blink` 三眨 | 1.2 s 内三次眨眼 | `⌘ + Tab`（切换应用） | ★★★ |
| `hard_blink` 重眨 | 单次眨眼力度 ≥ 校准阈值（用力挤眼） | 确认 Smart Brain 建议 | ★★★ |
| `long_blink` 长闭 | 闭眼时长 ≥ 400 ms（需要原始 EEG 才能测时长） | 切换"滚动模式"/ 紧急工作场景 | ★★★（依赖设备） |
| `blink_rate` 眨眼频率 | 滑动 60 s 窗口的眨眼次数 | 不做快捷键，供 Soft Heart 使用 | — |

用户可在设置里把任意眼势映射为：`click` / `right_click` / `double_click` / `keys:<组合键>` / `scene:<场景名>` / `brain_confirm` / `toggle_scroll` / `run:<脚本>`。

#### 4.1.2 校准（Calibration，首次使用约 60 秒）

1. 戴好设备，等待信号质量 OK（老鼠从"❓"变成"✅"）。
2. **自然阶段（20 s）**：正常看屏幕，采集自然眨眼分布。
3. **意图阶段**：屏幕提示"用力眨眼 ×10"，采集重眨分布。
4. **节奏阶段**：提示"快速双眨 ×5"，采集双眨间隔分布。
5. 自动计算阈值（重眨阈值取自然 P95 与意图 P50 中点等），保存到用户 profile。老鼠比心。

#### 4.1.3 反馈与防误触

- 每次眨眼老鼠同步眨眼（`blink_mirror`）；每次眼势识别老鼠头顶浮出图标，并有可关闭的轻音效。
- **信号质量差**（电极未贴合）时，所有眼势自动禁用，老鼠头顶显示"❓"。
- 眼势在识别后 500 ms 内不重复触发（防抖）。
- 提供全局开关（菜单栏 + 快捷键 `⌥⌘E`）；`Esc` 连按两次 = 停止一切正在执行的动作（全局急停）。

#### 4.1.4 设置界面

- 设备连接状态、信号质量条、实时眨眼波形（调试用，Demo 时可展示"这是你的脑电"）。
- 眼势 → 动作映射表（可编辑）。
- 校准按钮、灵敏度滑块。

### 4.2 🧠 SMART BRAIN —— 懂你工作的老鼠

**核心体验**：把"我在做什么工作"喂给老鼠 → 把光标移到某个应用上停一下 → 老鼠举牌建议要做的事 → 眨眼确认 → 老鼠替你开工。

#### 4.2.1 喂养（Feeding）

用户在设置界面的"喂养"页添加：

- 自我介绍 / 岗位 / 当前项目（自由文本）；
- 文件：Markdown、TXT、PDF、代码目录（只读扫描 README/目录结构）；
- 每个应用的"我希望你在这个 App 里帮我做什么"（可选，一句话）。

老鼠会把这些整理成一份 `profile.md`（"我对你的理解"），用户可查看和修改。**所有数据仅存本地** `~/.supermouse/brain/`，仅在调用 Claude API 时随请求发送。

#### 4.2.2 悬停识别（Hover Intent）

- 光标停在 **Dock 图标 / 应用窗口 / 桌面文件** 上 ≥ 700 ms（可调）→ 识别出目标应用（bundle id）或文件。
- 仅当目标应用 ≠ 当前前台应用，或悬停对象为文件时，才触发（避免在当前工作应用里到处弹建议）。
- 同一目标 30 s 内不重复建议。

#### 4.2.3 建议与确认（Suggest → Confirm）

- 老鼠进入 `thinking`，≤ 1.5 s 内进入 `suggest`，举牌显示一句话建议（≤ 20 字），例如：
  - Mail：*"要我起草今早 3 封未读邮件的回复吗？"*
  - VS Code：*"打开 hackathon 项目并列出今天的 TODO？"*
  - Notes：*"新建今天的日报草稿？"*
  - Chrome：*"打开你每天早上的 4 个标签页？"*
- 确认方式：**重眨 / 双眨**（Sharp Eyes 联动）或点击牌子；1.5 s 无操作则牌子淡出（移开光标也淡出）。
- 快路径：喂养完成后预生成每个常用应用的"默认计划"，悬停时直接展示（无网络延迟）；慢路径：结合当前屏幕截图实时生成（见文档 04）。

#### 4.2.4 执行（Act）

- 老鼠进入 `working`，通过 AppleScript / 快捷键 / 打字 / 打开 URL 等方式操作应用，执行进度在牌子上滚动显示（如"正在读取邮件 2/3"）。
- 完成后 `happy`，牌子显示结果摘要；失败显示原因。
- **安全边界**：发送消息、删除文件、支付等不可逆动作必须二次确认；只允许访问白名单目录；全局急停 `Esc Esc`。

#### 4.2.5 首批内置技能（Demo 用，可配置）

| 应用 | 技能 | 实现方式 |
|---|---|---|
| Mail | 起草未读邮件回复（存草稿不发送） | 截图 + 视觉理解 → AppleScript 创建草稿 |
| VS Code / Cursor | 打开指定项目，搜索 TODO 并汇总 | `code <dir>` + 读取文件 |
| Notes / Obsidian | 创建今日日报模板 | AppleScript / 写文件 |
| 浏览器 | 打开"早间套餐"标签组 | `open <url>` × N |
| Finder（文件悬停） | 总结这个文档 | 读取文件 → Claude 总结 → 牌子/通知展示 |

### 4.3 📡 STRONG SENSE —— 身后有人

**输入**：毫米波雷达（UART 串口，10 Hz 左右上报目标状态/距离/能量；多目标型号可给 x/y 坐标）。

#### 4.3.1 探测区与安装

- 雷达安装在显示器顶部，**朝向用户身后**（首选），探测区 0.8–4.0 m（可调）；
- 多目标雷达（如 LD2450）也可朝向用户，同时跟踪用户与身后来人（详见文档 03 §4.4）。

#### 4.3.2 触发规则

满足任一条件触发 `intruder`：

1. 探测区内**新出现移动目标**并连续 3 帧（约 300 ms）确认；
2. 目标**正在接近**：距离以 > 0.3 m/s 的速度减小。

触发后 20 s 冷却；探测区连续 10 s 无目标 → `clear`。

#### 4.3.3 工作场景（Work Scene）

用户预先配置：

- **摸鱼名单**：哪些应用算摸鱼（B 站、微信、游戏……）；
- **工作场景动作序列**（按顺序执行，总耗时目标 < 500 ms）：
  1. 隐藏摸鱼名单里的所有应用窗口；
  2. 激活指定工作应用（或切换到指定桌面 Space）；
  3. 静音；
  4. （可选）打开指定文档 / URL。
- **老鼠表现**：`alert` → 钻洞，`clear` 后探头。
- **仅在摸鱼时触发**（可选开关）：若当前前台应用不在摸鱼名单，则只做老鼠提示不切屏，减少误扰。
- **恢复**：`clear` 后老鼠探头询问"回去继续？"，双眨恢复之前的应用（可选）。

### 4.4 💗 第四模式（待定）

标题为 4 MODE，目前只定义了 3 个。候选方案（**均不需要新增硬件**）：

| 候选 | 内容 | 用到的信号 | 评价 |
|---|---|---|---|
| **SOFT HEART（推荐）** | 健康守护：眨眼频率 < 8 次/分持续 2 分钟 → 老鼠打哈欠提醒眨眼；久坐 50 分钟 → 提醒起身；专注度持续高 → 自动开启勿扰 | 脑机眨眼频率 / 专注度、雷达（朝向用户时）用户在座检测 | 命名与前三者押韵（S-开头 + 身体部位），有温度，实现成本低 |
| SWIFT PAWS | 手势宏：画圈=截图、甩动=撤销、摇晃老鼠=清理桌面 | 光标轨迹 | 好玩，但和硬件无关，卖点弱 |
| SILENT WHISKERS | 语音悄悄话：对老鼠小声说指令 | 麦克风 + Claude | 需新增语音链路，时间风险高 |

**建议**：今天内敲定，默认按 SOFT HEART 预留模块（文档 02 目录结构已留位），若时间不够，Demo 只展示 3 个模式 + 第四模式的概念图。

## 5. 模式联动（Synergy）

联动是"一只老鼠"而不是"三个功能"的关键：

- 眼势 **确认** Smart Brain 的建议（双手不离键盘完成整个流程）。
- Strong Sense 触发时，若 Smart Brain 正在执行任务，**暂停任务**并在 `clear` 后询问是否继续。
- 老鼠 `blink_mirror` 让脑机数据可见；Demo 时评委能直接看到"它真的在读你的眼睛"。
- 重眨 = 手动触发工作场景（"我自己知道老板来了"）。

## 6. 非功能需求

| 项 | 目标 |
|---|---|
| 眼势识别延迟 | 从眨眼结束到动作执行 ≤ 500 ms（双眨需等待 450 ms 判定窗口） |
| 眼势误触发 | 正常使用 10 分钟内误触发 ≤ 1 次 |
| 雷达 → 切屏延迟 | ≤ 600 ms（评委走到身后看清屏幕需要约 1–2 s） |
| 雷达误触发 | 无人经过 10 分钟内 0 次 |
| Overlay 帧率 | ≥ 60 fps 跟随，CPU 占用 < 10% |
| 隐私 | 脑电原始数据不出本机；喂养内容仅本地存储 |
| 权限 | 首次启动引导授予：蓝牙、辅助功能、屏幕录制、自动化 |
| 可降级 | 任一硬件缺失时，对应模式可用键盘模拟器替代，Demo 不中断 |

## 7. 设置项汇总

对应 `~/.supermouse/config.yaml`（完整规范见文档 02 §6）：

- 设备：脑机设备名/协议、雷达串口/型号
- Sharp Eyes：开关、校准参数、眼势映射表、灵敏度
- Smart Brain：开关、悬停时长、确认方式、应用技能配置、知识目录
- Strong Sense：开关、探测区、冷却、摸鱼名单、工作场景动作序列、仅摸鱼时触发
- 老鼠：皮肤、是否隐藏系统光标、音效开关

## 8. 用户故事与验收标准

**US-1 眼势点击**
Given 已完成校准且信号质量 OK，When 用户快速双眨，Then 在光标位置产生一次左键点击，老鼠播放 `click` 动画，端到端延迟 ≤ 500 ms。

**US-2 校准**
Given 首次使用，When 用户完成 60 s 校准流程，Then 生成阈值并保存，随后 2 分钟自然使用无误触发。

**US-3 悬停建议**
Given 已喂养工作内容并配置 Mail 技能，When 光标悬停 Dock 中 Mail 图标 700 ms，Then 老鼠 1.5 s 内举牌给出建议。

**US-4 确认并执行**
Given 老鼠正在举牌，When 用户重眨，Then 老鼠打开 Mail 并创建草稿，完成后 `happy` 并展示摘要。

**US-5 老板键**
Given 用户前台为 B 站且已配置工作场景，When 有人从 3 m 处走到用户身后 1 m，Then ≤ 600 ms 内 B 站隐藏、VS Code 前台、静音，老鼠钻洞。

**US-6 降级**
Given 脑机未连接，When 用户按下模拟快捷键 `F13`，Then 系统产生一次等效的双眨事件，后续流程一致。

## 9. 开放问题

1. 第四模式最终选择（§4.4）。
2. 脑机是否输出原始 EEG（决定 `long_blink` 是否可用）—— 明天到货确认。
3. 雷达型号是单目标（LD2410 类）还是多目标（LD2450 类）—— 决定安装朝向与算法分支。
4. Smart Brain 的执行是否允许"发送"类动作（建议 Demo 阶段一律只到草稿）。
5. 是否需要 Windows 支持（建议黑客松阶段仅 macOS）。
