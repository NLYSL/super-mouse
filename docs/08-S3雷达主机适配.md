## 生效配置

已备份并仅修改用户配置中的 radar 区段，未改眼势映射、工作场景或其他偏好。
备份：`~/.supermouse/config.yaml.before-s3-20260912-225731.bak`。

```yaml
devices:
  radar:
    connection: micropython
    model: bridge
    baud: 115200
    port: auto
sense:
  intruder_target_count: 2
```

继续用 `auto`，它只接受当前 CH340K 身份，不随 USB 节点变动失效；若出现多个 CH340K 候选，再指定实际端口。
原生 USB `303A:4001` 和脑机 `1A86:5722` 不属于雷达候选。WCH 缺失 VID/PID 元数据时仅接受无身份冲突的 `wchusbserial` 节点名。

## 改动

### 文本解析

`BridgeTextParser` 使用 `firmware/ld2454_micropython/main.py::report` 的真实中文格式：

```text
#000001 T1: x=-782mm y=1713mm v=-16cm/s 距离=1.88m 角=-24.5° 分辨率=320mm | T2: 无 | T3: 无
```

- 逐字节、每 7 字节、中文 UTF-8 跨块均可正确重组。
- 每行必须有完整且唯一的 T1/T2/T3 槽位；非法、截断、重复槽位、超长行不会变成“无人”事件。
- 忽略 RAW hex、启动横幅及配置诊断，避免同一雷达帧被重复计数。
- 距离从 x/y 重算；`moving_cm` 只取运动目标，不把更近的静坐用户距离当运动目标距离。
- 文本和二进制共用事件构造函数，保持 `radar.frame` 字段不变，文本协议的 model 为 `bridge`。

### 串口与主程序

- `connection: micropython` 只读，不发送 Arduino 的 `!info/!scan/!pins/!multi`，也不发送 `r`、Ctrl-C 或复位字符。
- 打开前设置 DTR/RTS=False；有限读写超时，POSIX 独占锁；不清空第一批输入。
- 断线重建解析器，设备暂缺时持续等待正确端口，不回退到 REPL。
- 脑机自动选口也改为确定的身份匹配，防止 CH340K 与脑机同 VID 造成串口争抢；其他脑机需要显式配置端口。
- `sense.intruder` / `sense.clear` 契约与第二人判定保持原样。

### 工具与兼容

- `radar_probe.py` 默认按当前配置只读抓包，统计完整文本/二进制帧数、人数分布和实际平均帧率。
- `--list` 仅显示端口身份；离线 `--analyze` 不打开串口。
- MicroPython 模式拒绝旧 `--scan/--pins/--multi/--radar-baud`；旧 Arduino 桥必须显式选择 `--connection arduino`。
- `--baud` 表示主机侧速率；macOS/Linux 的采集硬超时覆盖串口打开与读取，退出关闭端口。
- 自检区别“找到串口”与“已验证雷达帧”，不再把空抓包算作硬件成功证据。

## 已知边界

- 资料中的标称约 10 Hz 与 Windows 记录 168 帧/10 秒不同；主机不硬编码帧率，也不宣称 16.7 Hz 与 10 Hz 相同。
- 单次仅看到一个目标并不能证明多目标配置失败；配置成功日志也不能替代双人实测。
- 运动雷达能否稳定跟踪静坐本人必须实测。若本人丢跟踪，单纯增加 min_frames 不会消除漏判。
- 板上“3秒未收到数据”的告警文字仍写 D7/D6，属于旧提示；实际 S3 UART1 是 G10/G11。保留已跑通的脚本不修改。
