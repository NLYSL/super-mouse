## 2. 当前阻塞：CH340K 差一个 PID（已验证）

macOS **认得这个 USB 设备，但不给它建串口节点**：

```
USB 总线上存在： 1A86:7522  "USB Serial"     ← CH340K 在
/dev/cu.* 里只有：
    /dev/cu.usbmodem11401      VID 0x303A PID 0x4001  ← S3 原生 USB（MicroPython REPL）
    /dev/cu.usbmodem2017_2_251 VID 0x1A86             ← 脑机，别碰
    /dev/cu.debug-console                             ← 同一颗 S3 的 JTAG，不是它
```

**根因**：macOS 15.5 自带 `com.apple.DriverKit-AppleUSBCHCOM.dext` 只匹配
`idProduct = 29987 (0x7523)` 和 `21972 (0x55D4)`。
这颗 CH340K 是 **0x7522** —— 差一个数字，所以没有驱动绑上去。

代码绕不过去，必须装驱动。

### 已排除的可能（别重复试）

| 试过什么 | 结果 |
|---|---|
| 读 `/dev/cu.usbmodem11401`（115200 / 256000，DTR 高与低都试） | **0 字节**。它是 REPL 口，烧录记录里明确写「本方案未使用」 |
| 读 `/dev/cu.debug-console` | 打开成功，0 字节。是 S3 的 JTAG 调试口 |
| 1200 波特率触碰想催出 ROM 下载口（PID 0x1001） | 没出现 |
| esptool 连 `usbmodem11401` | 连不上 —— MicroPython 占着，**这是正常现象，不是故障** |

## 4. 数据格式（逐字摘自 `main.py`，已验证）

`main.py` 第 113–124 行：

```python
def report(frame_no, frame, targets):
    if RAW_HEX:
        log("RAW: " + " ".join("%02X" % b for b in frame))
    parts = []
    for i, t in enumerate(targets):
        if t is None:
            parts.append("T%d: 无" % (i + 1))
        else:
            x, y, v, res, dist, ang = t
            parts.append("T%d: x=%dmm y=%dmm v=%dcm/s 距离=%.2fm 角=%.1f° 分辨率=%dmm"
                         % (i + 1, x, y, v, dist, ang, res))
    log("#%06d %s" % (frame_no, " | ".join(parts)))
```

实际一行长这样（**注意以 `#` 开头**）：

```

```

要点：

- **是文本，不是二进制帧** —— 项目里现成的 `LD2410Parser`/`LD2450Parser`/`LD2454Parser` 全对不上
- 目标不存在时是 `T2: 无`
- 坐标符号已在板上处理好（协议表9 的「最高位 1 为正」怪约定，`main.py` 的 `signed()` 已还原）
- 速度为**负 = 朝雷达靠近**
- `RAW_HEX` 打开时还会有 `RAW: AA FF 03 00 …` 行，要跳过
- 启动横幅、`[配置]` 之类的行也要跳过

## 6. 已经踩过的坑（别重复）

### 6.1 pyserial 的 DTR 会复位 ESP32 ★

ESP32 把 DTR 当复位线，而 pyserial 打开端口时**默认置位 DTR**
→ 芯片被按在复位状态 → **端口能打开但读到 0 字节**。

```python
ser = serial.Serial()
ser.port = "…"; ser.baudrate = 115200
ser.dtr = False      # ← 必须在 open() 之前
ser.rts = False
ser.open()
```

`serial_client.py` 已这样处理。**写任何新调试脚本都要注意。**

### 6.2 型号/固件搞错会让整个方向偏掉 ★

先后错过两次：
- 一开始按 **LD2401** 手册排查（那份写 3.3V、有 OUT 引脚），LD2454 其实是 5V、没有 OUT
- 后来以为板上是 Arduino，一直想用 esptool 刷 `radar_bridge.ino` —— 实际是 MicroPython

**只认 `firmware/ld2454_micropython/` 里的 `main.py` 和烧录记录。** 别用其他型号/方案类推。

顺带：`firmware/radar_bridge/radar_bridge.ino`（Arduino 桥）对这块板子**已经无用**，
它走的是完全不同的路线。别去改它，也别刷它。

### 6.3 串口读取脚本容易把 shell 挂死

我有好几条命令因为 pyserial 卡在 `open()`/`read()` 上超时进了后台，
后台进程还继续占着端口，导致后续读取全是 0 字节 —— **自己制造的假象**。

写调试脚本务必加硬超时，并在重试前确认端口没被占：

```python
import signal
signal.signal(signal.SIGALRM, lambda *a: (_ for _ in ()).throw(TimeoutError()))
signal.alarm(20)          # 无论卡在哪，20 秒必退
```

```bash
lsof /dev/cu.wchusbserial*      # 确认没人占着
pkill -f "你的脚本名"
```

### 6.4 别只看 `p.vid` 过滤串口

我用 `if p.vid` 过滤 `list_ports.comports()`，把没有 VID 元数据的
`/dev/cu.debug-console` 整个漏掉了，白绕一圈。列设备时先看全量 `ls /dev/cu.*`。
