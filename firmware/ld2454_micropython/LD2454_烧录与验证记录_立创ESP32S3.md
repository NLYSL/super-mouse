# HLK-LD2454 雷达 · 立创 ESP32S3R8N8 烧录与验证记录

> 日期：2026-09-12
> 背景：XIAO ESP32-C6 上雷达始终无响应，换成立创·ESP32S3R8N8 开发板后重新烧录固件并调试，最终全链路打通。
> 本文档整理自换板之后的完整操作过程，可作为以后重烧/迁移的参考。

---

## 1. 硬件连接

| 开发板 | 立创·ESP32S3R8N8（ESP32-S3，8MB Flash + 8MB PSRAM） |
|--------|------|
| 雷达 T（UART_TX） | **G10**（GPIO10，UART1 RX） |
| 雷达 R（UART_RX） | **G11**（GPIO11，UART1 TX） |
| 雷达 5V | 板上 5V/VBUS |
| 雷达 G | GND |

接线为标准的交叉接法：雷达发→板收（T→G10），板发→雷达收（R→G11）。

## 2. 操作过程

### 2.1 串口识别

新板上电后出现两个串口：

| 串口 | 设备 | 用途 |
|------|------|------|
| **COM6** | USB-SERIAL CH340K（VID_1A86&PID_7522） | 接 UART0，MicroPython REPL / 数据输出，**用这个** |
| COM5 | Espressif 原生 USB（VID_303A&PID_4001） | S3 原生 USB，本方案未使用 |

### 2.2 固件选择

- 目标固件：MicroPython v1.29.0（2026-08-24）`ESP32_GENERIC_S3` 版
- 注意：S3 与之前 XIAO 用的 C6 固件**不通用**，必须用 ESP32_GENERIC_S3 专用 bin
- 本板是 R8（八线 PSRAM），理想是 SPIRAM_OPI 变体，但官网该文件名 404；**基础版完全够用**（PSRAM 初始化失败的警告可以忽略，系统提示 "continuing without it"，不影响串口功能）

### 2.3 擦除与烧录

```bat
:: 擦除原厂固件
D:\claw\tools\python312\python.exe -m esptool --chip esp32s3 --port COM6 --baud 460800 erase_flash

:: 烧录 MicroPython 固件（写入地址 0x0）
D:\claw\tools\python312\python.exe -m esptool --chip esp32s3 --port COM6 --baud 460800 write_flash 0x0 "D:\项目\2454\firmware\ESP32_GENERIC_S3-v1.29.0.bin"
```

- 擦除时 esptool 正确识别：`ESP32-S3 (QFN56) rev 0.2，Embedded PSRAM 8MB`
- 烧录 1,783,296 字节，`Hash of data verified` 校验通过

### 2.4 上传雷达脚本 main.py

```bat
D:\claw\tools\python312\python.exe -m mpremote connect COM6 cp "D:\项目\2454\firmware\main.py" :main.py
```

main.py 的关键配置（改硬件接法时只动这几行）：

```python
RADAR_BAUD   = 256000
RADAR_TX_PIN = 11   # G11 -> 雷达 R
RADAR_RX_PIN = 10   # G10 <- 雷达 T
TRACK_MULTI_TARGET = True   # 多目标追踪（最多 3 个）
```

脚本开机自动执行：使能配置(0x00FF) → 多目标追踪(0x0090) → 结束配置(0x00FE)，然后持续解析数据帧并打印。

### 2.5 过程中遇到的两个坑

1. **SPIRAM_OPI 固件下载失败**：官网返回 404 页面但 curl 静默保存成了 162 字节的假文件，第一次烧录只写入了 164 字节且无校验输出。教训：烧录后必须确认输出里有 `Hash of data verified`，以及文件大小是否正常。
2. **mpremote 上传与开机输出抢串口**：烧录后立即 `cp` 会报 `could not enter raw repl`。等板子停在 REPL（或先复位一次）再上传即可。

## 3. 验证结果

### 3.1 配置命令全部 ACK 成功

```
[配置] 使能配置: 成功
[配置] 多目标追踪: 成功
[配置] 结束配置: 成功
```

### 3.2 数据流

- 帧率约 **16.7 帧/秒**（10 秒收到 168 帧），符合 LD2454 标称刷新率
- 目标轨迹连续、速度/角度物理上合理（可清晰还原人在雷达前的走动路径）
- 输出示例：

```
#000921 T1: x=0mm y=164mm v=0cm/s 距离=0.16m 角=0.0° 分辨率=330mm | T2: 无 | T3: 无
#000982 T1: x=38mm y=195mm v=17cm/s 距离=0.20m 角=11.0° 分辨率=330mm | T2: 无 | T3: 无
```

字段说明：x/y 为毫米坐标（y+ 为雷达正前方，x+ 为右方）；v 为径向速度（cm/s）；距离与水平角由坐标换算；目标不存在时显示"无"。

## 6. 附：XIAO ESP32-C6 为什么不通（诊断结论）

在 XIAO C6 上（T→D7、R→D6，与协议文档一致）曾做如下诊断：

- 全引脚 × 7 种波特率嗅探：雷达相关引脚**零字节**；
- 上拉/下拉电平检测：雷达 TX 所在引脚被稳定驱动为高电平（UART 空闲态）→ **雷达供电正常**；
- 但对任何配置命令无 ACK，雷达从不发送任何数据。

同样的接线换到立创 S3 板后一次即通。结论：雷达模块本身没坏，问题出在 XIAO 那套连接上（杜邦线/排针接触不良的可能性最大）。XIAO C6 的 Flash 里现在也是这套 MicroPython 固件，用 `main_xiao_esp32c6.py` 即可恢复。

## 7. LD2454 协议速查（摘自《LD2454串口通信协议 V1.00》）

- 串口参数：**256000，8N1**，TTL 3.3V 电平
- 上报帧（约 16 帧/秒，无需命令即持续输出）：`AA FF 03 00` + 目标1×8B + 目标2×8B + 目标3×8B + `55 CC`
- 单目标 8 字节 = x(2B) + y(2B) + 速度(2B) + 距离分辨率(2B)，均为小端 int16；**最高位 1=正、0=负**，低 15 位为幅值；目标不存在时该 8 字节全 0
- 命令帧：`FD FC FB FA` + 长度(2B) + 命令字(2B) + 命令值 + `04 03 02 01`；ACK 的命令字 = 原命令字 | 0x0100，其后 2 字节为状态（0=成功）
- 常用命令：使能配置 `0x00FF`(值 0x0001，任何命令前必须先发) / 结束配置 `0x00FE` / 多目标 `0x0090` / 单目标 `0x0080` / 读版本 `0x00A0` / 设波特率 `0x00A1` / 恢复出厂 `0x00A2` / 重启 `0x00A3`
